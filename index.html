How it works
Agentic workflow.
Not autocomplete.

Every task follows a research-first approach. The plugin reads issues, studies past PRs, and builds a plan — then waits for you.

Self-improving
The plugin gets
better every session.

Every Claude Code session is evaluated asynchronously. Gaps in skill guidance are captured, verified, and presented for your decision. Only you can approve a fix.

1
You start a Claude Code session
You open Claude Code in an etcd-druid checkout and invoke /etcd-druid:plan or /etcd-druid:implement on a real issue. The plugin's skills guide the workflow — plan, code, review.
automatic
2
Async evaluation detects a gap
After the Claude Code session ends, an async evaluation compares what the plugin's skills instructed against what actually happened in the conversation. If a skill gave wrong guidance, missed a footgun, or had an outdated workflow step — it's flagged as an observation.
async — runs after your session ends
3
Structured observation saved
Each gap is captured as a structured observation with: the type of error, evidence from the conversation (what was wrong), a suggested fix, and which skill file to update.
4
Next Claude Code session: you triage
When you start your next Claude Code session, /etcd-druid:observations loads all pending observations. Each one is pre-verified against the current skill files. For each observation, you choose:
Raise PR — fix the skill
Skip — not now
Dismiss — not a real gap
5
Plugin improves
If you chose "Raise PR", the plugin opens a PR against its own skill files. Once merged, every future Claude Code session benefits from the corrected guidance. No skill is ever modified without your explicit approval.
only on your approval
↺  Next Claude Code session starts at step 1 — the cycle repeats

FAQ
Common questions.
Does it modify my repo files?

No. The plugin only affects your Claude Code session context — it reads your repo but never writes to it directly. All code changes are made by Claude through normal tool calls that you approve.

What Claude model do I need?

claude-sonnet-4-5 or newer. Opus is recommended for plan and implement skills. The Haiku floor was raised — it won't activate on Haiku.

Does it work offline?

The plugin itself is local — skills and hooks run in your Claude Code session. But Claude Code requires an internet connection to the Anthropic API.

Can I use it on other repos?

It's built specifically for gardener/etcd-druid, gardener/etcd-backup-restore, and gardener/etcd-wrapper. It auto-detects which repo you're in and adjusts conventions accordingly. You can also clone the plugin and point to it locally when starting Claude: claude --plugin-dir /path/to/etcd-druid-skills

How do I contribute a new footgun or skill?

Edit skills/<name>/SKILL.md and open a PR. For new cross-cutting guides, add a skill with user-invocable: false. See the Contributing guide.

What are the known limitations?

The plugin encodes conventions as of the current master branch. For older release branches, some make targets and file paths may differ. Cross-repo e2e testing (e.g. testing backup-restore changes via etcd-druid) requires manual image push to a local registry.
